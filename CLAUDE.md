## Overview

`pikru-node` exposes the Rust crate [`pikru`](https://crates.io/crates/pikru) (a Pikchr→SVG renderer) to JavaScript via WebAssembly. The entire JS API surface is a thin wasm-bindgen wrapper in `pikru-wasm/src/lib.rs` — there is no hand-written JS; `node/dist/` is generated by wasm-bindgen and not committed.

## Architecture

There is one Rust crate (`pikru-wasm`) with two distinct build targets, each producing a different binding flavor from the same `.wasm`:

- **Node.js package** (`node/`, published as `@tmke8/pikru`): built via `npm run build`, which runs `cargo build` then `wasm-bindgen --target experimental-nodejs-module`, emitting ES modules into `node/dist/`.
- **Web playground** (`playground/`): built via the `Makefile`, which runs `cargo build` then `wasm-bindgen --target web` into `playground/pkg/`, then optimizes with `wasm-opt`.

The `Pikru` struct in `lib.rs` holds a `pikru::RenderOptions`. Options are passed from JS as a plain object typed (for TypeScript consumers) by the `typescript_custom_section` `RenderOptions` interface; the `extern "C"` getter block bridges JS object properties (`cssVariables`, `explicitSize`) into Rust. `render()` returns `Result<String, String>`, which wasm-bindgen surfaces to JS as a thrown exception on error.

When changing the options API, three places must stay in sync: the `RENDER_OPTIONS_DEF` TS interface, the `extern "C"` getters, and the `RenderOptions` construction in `Pikru::new`.

## Commands

All Node commands run from `node/`:

```bash
cd node
npm install
npm run build      # cargo build + wasm-bindgen → node/dist/ (required before test)
npm test           # mocha; tests import from ../dist/, so build first
```

Run a single test by mocha grep:

```bash
cd node && npx mocha --grep "should render simple diagram"
```

Web playground build (from repo root; requires `wasm-opt` from binaryen):

```bash
make playground   # → playground/pkg/
python3 -m http.server 8000 --directory playground
```

## Build requirements & version coupling

- Building requires the `wasm32-unknown-unknown` Rust target and the `wasm-bindgen` CLI.
- The `wasm-bindgen` CLI version must exactly match the `wasm-bindgen` library version in `Cargo.lock`. CI derives this version from `Cargo.lock` and installs the matching CLI — a mismatch produces a runtime/binding error, not a clear message. After bumping the `wasm-bindgen` dependency, reinstall the matching CLI locally.
- `pikru` and `pikru-wasm` versions are kept in lockstep (currently 1.2.1 in `pikru-wasm/Cargo.toml`).
- Release profile is tuned for binary size (`opt-level = "s"`, `lto`, `codegen-units = 1`); keep this when touching `Cargo.toml`.
